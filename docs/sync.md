# 작업마다 Git 동기화

기본 CLI와 MCP는 모든 업무·지식 조회 및 변경을 다음 순서로 처리한다.

1. 브랜치·upstream·현재 작업 상태를 검사한다.
2. 지정된 upstream에서 `git pull --ff-only`로 최신 기록을 받는다.
3. 원본 파일을 검증하고 요청한 업무를 처리한다.
4. 변경이 생겼으면 해당 registry JSON만 stage·commit한다.
5. 지정된 upstream 브랜치로 push한다. 성공한 뒤에만 호출 결과를 반환한다.

조회도 2·5단계를 수행한다. 변경이 없으면 새 커밋은 만들지 않는다. 계획 저장, 결과 기록, 지식 문서 수정, 담당 선언도 각각 이 절차를 거친다. 실시간 담당 잠금 대신 자주 동기화하는 운영 규칙이다.

## 처음 준비할 것

두 개발자는 같은 사내 업무 전용 저장소를 각각 clone하고 같은 공용 브랜치의 upstream을 설정한다. 해당 PC에 Git 작성자와 저장소 인증을 준비한다. 자동 공유 대상은 업무·문서·감사 이력이다. 개발 코드 저장소는 기존 팀 규칙을 따른다.

이 프로젝트의 공유 저장소는 `https://github.com/holywaterBetter/task-manager.git`다. 빈 저장소를 새로 운영할 때는 README 등 최초 커밋을 공용 브랜치에 한 번 push하고 upstream을 설정한 뒤 도구를 연결한다.

깨끗한 작업 폴더가 필요하다. 이미 수정한 파일, 별도 미공유 커밋, detached HEAD, 진행 중인 merge/rebase가 있으면 먼저 정리한다. 기존 변경을 자동으로 stash하거나 개인 커밋을 임의로 push하지 않는다. 네트워크와 인증도 조회 시마다 필요하다.

## 실패 처리

| 실패 시점 | 상태와 대응 |
| --- | --- |
| 사전 점검·pull | 업무 변경을 시작하지 않는다. Git 설정·기존 변경·접속 상태를 확인한다. |
| 버전·업무 검증 | 동기화로 바뀐 최신 내용을 다시 읽고 요청을 재검토한다. |
| commit | 업무 파일이 로컬에 남을 수 있다. 결과를 다시 생성하지 말고 Git 상태와 오류를 확인한다. |
| push | 로컬 변경·커밋을 보존하고 공유 미완료로 응답한다. 원래 업무를 반복 실행하지 않는다. |

push 실패 뒤에는 새 업무 호출을 막는다. 기존 커밋만 다시 전송한다.

```bash
python3 /path/to/task-manager/team_tasks.py --registry /path/to/team-work/registry sync-retry
```

MCP에서는 `sync_retry`를 사용한다. 이 기능은 task.create나 원래 변경을 다시 실행하지 않는다. 전송하려는 커밋·브랜치·작업 상태가 바뀌었으면 중단한다.

원격이 먼저 변경돼 push가 거절됐으면 접속 재시도만으로 해결되지 않는다. 로컬 변경을 보존하고 양쪽 이력을 확인해 팀의 merge/rebase 절차로 해결한다. 프로그램은 강제 push·자동 충돌 해결을 하지 않는다. 복구 후에는 업무를 다시 읽고 version을 확인한다.

직접 병합해 새 커밋으로 push한 뒤에는 다음 명령으로 복구 완료를 확인한다.

```bash
python3 /path/to/task-manager/team_tasks.py --registry /path/to/team-work/registry sync-resolved
```

MCP에서는 `sync_resolved`다. 보존된 업무 커밋이 현재 이력에 포함되는지, 원본 파일이 유효한지, 원격과 현재 HEAD가 일치하는지 검사한 뒤에만 공유 미완료 표시를 해제한다. 이 명령은 새 커밋을 push하거나 병합하지 않는다.

## 로컬 전용 실행

`--local-only`를 명시하면 이전의 파일 기반 로컬 도구로 실행한다. 샘플·개발 테스트 또는 사용자가 별도로 지정한 로컬 작업용이다. 기본 동기화가 실패했다고 자동으로 이 모드로 전환하지 않는다. 실제 업무의 최신 상태·공유 완료를 주장하는 데 사용하지 않는다.

일반 Git 명령이나 외부 편집기가 같은 폴더를 수정하는 동안 도구를 동시에 실행하지 않는다. 도구끼리는 로컬 Git 잠금으로 pull부터 push까지 직렬화한다. 다른 PC와의 실시간 잠금은 제공하지 않는다.
