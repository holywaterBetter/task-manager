# 검증 기록

## v0.2 — 작업마다 Git 동기화

2026-10-26, Linux / Python 3.12.3. 전체 **70개 테스트 통과**. Codex 스킬 검증과 Python 구문 검사도 통과했다.

기본 CLI/MCP가 동기화를 생략하지 않는지, 모든 조회·변경에서 pull·push하는지, 변경 JSON만 커밋하고 조회 시 빈 커밋은 만들지 않는지 확인했다. 이전 로컬 실행은 명시적 `--local-only`로 유지했다.

실제 로컬 bare 원격과 두 clone으로 정상 왕복, push 경쟁 거절, 통신 실패·응답 유실 후 동일 커밋 재전송, 수동 병합·push 완료 검증 후 재개를 확인했다. 기존 작업 파일·미공유 커밋·진행 중 Git 작업은 차단했다. 사용자 Git 설정의 자동 태그 전송, 업무 외 파일이 추가되는 hook, 서로 다른 fetch/push 목적지의 복구 확인도 검증했다. 동기화 전용 테스트는 21개다.

MCP의 복구 도구가 업무 생성을 다시 실행하지 않는지도 확인했다. 기본 동기화 모드에는 업무 도구 16개와 복구 도구 2개를 제공한다. 실제 사내 PC나 Windows/macOS 검증은 포함하지 않는다.

## v0.1 — 최초 파일 기반 버전

2026-10-26, Linux / Python 3.12.3에서 확인했다.

- `python3 -m unittest discover -s tests -v`: **47개 테스트 통과**.
- 실제 stdio 하위 프로세스: MCP 초기 연결, 16개 도구 발견, 한글 프로젝트 생성·조회, 비정상 Unicode ID 이후 후속 요청 처리 확인.
- Codex 스킬 검증기: `codex-skills/team-tasks` 통과.
- `compileall`: Python 소스 구문 검사 통과.
- `examples/registry`의 합성 샘플을 `examples/vault`로 내보내고 원본 정합성 검사 통과.

Git 왕복 테스트는 임시 bare 저장소와 Alice/Bob의 두 clone을 실제로 생성했다. 서로 다른 업무 생성·커밋·병합·push/pull 뒤 양쪽 파일과 감사 이력이 같은지 확인했다. 같은 업무를 같은 버전에서 선점하면 두 로컬 호출은 모두 성공할 수 있음을 재현하고, 이후 push 경쟁·Git 충돌과 미해결 상태에서의 수정 거부를 확인했다. 테스트는 로컬 경로만 사용했으며 사내 Git이나 네트워크에 접속하지 않았다.

별도 검토에서 발견한 담당 지정 우회, ID 충돌 시 기록 보존, 긴 설명이 선택 업무의 요청을 밀어내는 문제, 비정상 MCP 입력으로 프로세스가 종료되는 문제를 수정하고 회귀 검사했다.

Obsidian 결과는 링크 대상 파일의 존재, YAML 속성 이스케이프, 계층·선후행 참조, 최하위 업무 진척·배분, 기존 노트 보호, 반복 내보내기, 경로·심볼릭 링크 처리를 검증했다. 실제 Obsidian 앱에서의 렌더링은 확인하지 않았다.

사내 Git 서버 접근, 두 실PC의 Codex App 설정, Windows/macOS 실행은 아직 검증하지 않았다. Git 최신 상태와 PC 간 실시간 선점을 보장하는 테스트 결과로 해석하지 않는다. 이 단계는 작은 과제로 실제 운영 흐름을 검증할 수 있는 프로토타입이다.
